# 无旁白音乐图文视频（Remotion）

这个 Skill 只提供流程、标准和工具。主题、文案、配色、视觉风格都来自当前项目和用户，不要套用以前某支视频的内容。仓库里已有的合成（例如 ShunYingDaNao）可以当写法参考，只读不改。

命令都在仓库根目录执行；Skill 不在 `.agents/skills/music-graphic-video/` 时，把脚本路径换成实际位置。

## 开工前

1. 读仓库的 `README.md`。合成放在哪、怎么注册、素材目录、类型校验和渲染命令都以它为准；下文的默认路径只在 README 没写时使用。
2. 跟用户确认以下信息，缺哪项问哪项，不要猜：主题和文案来源、目标时长、目标平台和画幅（决定安全区）、BGM 文件（1～2 首）、视觉参考图、视觉风格。
3. 检查工具：`ffmpeg`、`ffprobe`、`python3`、numpy（`python3 -m pip install numpy`）、fontTools（`python3 -m pip install fonttools`）。缺了就告诉用户安装命令，不要跳过对应的检查。
4. 找音效用已安装的 `sound` skill；没有的话按 [references/audio.md](references/audio.md) 的“音效来源”手动找 CC0 素材。

## 四阶段门禁

每个阶段结束时：把产物写成文件，向用户汇报要点和待确认的问题，然后**停下来等用户确认**，确认之前不开始下一阶段。用户明确说“跳过”或“直接做”时可以跳，在产物的确认记录里写明。用户改了上游（换 BGM、改时长、改文案）时，回到对应阶段，下游重做。

产物放在 README 规定的位置；没有规定时放 `docs/<合成名>/`。文件名带主题前缀，避免覆盖其他视频的文档。

| 阶段 | 产物 | 模板 |
|---|---|---|
| 1 | `<主题>_BGM分析与衔接方案.md`，附脚本报告 `bgm_probe.md` / `bgm_probe.json` | [assets/audio-plan-template.md](assets/audio-plan-template.md) |
| 2 | `<主题>_分镜与制作文档.md`，附音效清单 `sfx.csv` | [assets/storyboard-template.md](assets/storyboard-template.md)、[assets/sfx-manifest-template.csv](assets/sfx-manifest-template.csv) |
| 3 | 新合成代码和素材；在分镜文档末尾追加 Studio 抽查清单 | 分镜模板第 7 节 |
| 4 | 成片 MP4；在分镜文档末尾追加审片修改和成片复测，文档改名为 `<主题>_最终版分镜与制作文档.md` | 分镜模板第 8、9 节 |

### 阶段 1 · 音频体检与衔接方案

这个阶段只做分析：不写合成代码，不下载音效。

```bash
python3 .agents/skills/music-graphic-video/scripts/audio_probe.py music/A.mp3 [music/B.mp3] \
  --target 60 --fps 30 --out docs/<合成名>/bgm_probe.md --json docs/<合成名>/bgm_probe.json
```

报告包含时长、综合响度（LUFS）、响度范围、True Peak、BPM 与半速/倍速候选、拍点贴合度、小节首拍估计、每 5 秒的响度和律动、段落抬升/回落、天然气口、只压不抬的音量系数，以及起播点、切出点、收尾点的候选和 Remotion 帧参数。怎么读见 [references/audio.md](references/audio.md)。

按模板写方案，向用户汇报：

- 音量系数：哪首压多少 dB、为什么。只压偏响的音轨，系数 = 10^(dB/20)，永远 ≤ 1。
- 起播点：前 15 秒有没有推进感。是慢前奏的话，换到能量抬升处起播，或者在分镜里让画面撑住钩子。
- 切歌：A 在哪个气口或段落回落切出，B 从哪里接入，交叉淡化多长，衔接处响度变化多少。
- 收尾：落在哪个乐句末尾，淡出多长。
- 需要用户听辨的点：置信度不是“高”的 BPM、小节首拍、半速/倍速候选。

### 阶段 2 · 分镜脚本与音效规划

输入是用户确认过的音频方案、视觉参考图和 `sound` skill。这个阶段也不写代码。

1. 先定视觉系统（一页）：色板、字体和字号阶梯、线宽与圆角、质感、2～3 条统一的缓动曲线、4～6 个动效词汇。按风格选词汇，见 [references/visual.md](references/visual.md)。
2. 逐镜写分镜。每一镜有自己的视觉隐喻，在视觉系统之内变化；不做 PPT 式的文字轮播。
3. 每一镜的停留时长按红线 1 计算并写进表格；卡点吸附到阶段 1 的拍点、小节首拍和气口，秒和帧都写。
4. 画面密度跟着报告里的“级别”和“律动”走：低/疏的段落元素少、运镜慢，高/密的段落才上连击和重拍冲击。
5. 文案在分镜里就手动断好行（见 references/visual.md 的中文排版）。
6. 列音效点位清单：时间（帧）、对应动作、音效类型、长度上限、CC0 来源候选。
7. 写清前 3 秒的钩子和结尾的收法。

### 阶段 3 · 隔离开发与本地预览

1. **隔离**（README 规定得更具体时以 README 为准）：
   - 新合成用新的 id，代码放在自己的目录（例如 `src/<合成名>/`）。
   - `src/Root.tsx` 只追加一个 `<Composition>`，不改其他条目。
   - 公共组件要改的话，复制到新合成目录里改，原件不动。
   - 素材放 `public/<合成名>/`，渲染输出用新文件名。`remotion.config.ts` 里有 `setOverwriteOutput(true)` 时，同名输出会被直接覆盖。
   - 写完后用 `git status`、`git diff --stat` 确认改动只落在新目录、新素材目录和 `Root.tsx` 的追加行。
2. **音效**：用 `sound` skill 下载，填 `sfx.csv`，再用 `prep_sfx.py` 统一处理（见红线 5）。
3. **自动检查**，按顺序跑：
   - 类型校验：`npx tsc --noEmit`，或 README 里的 typecheck 命令。
   - 字形扫描：`python3 .agents/skills/music-graphic-video/scripts/check_glyphs.py --font <每个字体文件> src/<合成名> [文案数据文件]`。有“所有字体都缺”的错误先修。
   - 静止检测：先渲一个低清预览 `npx remotion render <合成id> out/qa/<合成名>-preview.mp4 --scale=0.5`，再跑 `python3 .agents/skills/music-graphic-video/scripts/check_freeze.py out/qa/<合成名>-preview.mp4 --allow <爆点定格区间>`。这个预览只用于检查，不算正式成片。
4. **预览**：在后台启动 Remotion Studio（`npx remotion studio`，不要阻塞会话），把地址和抽查清单发给用户。抽查清单按帧号列：钩子区、每个大幅推镜或特写的首帧和停留末帧、每个分步揭示的触发前一帧、每个爆点、切歌点、最后 3 秒。
5. 不渲染正式成片，等用户审片。

### 阶段 4 · 精修与成片导出

1. 把审片反馈集中改完，改动仍然只限新合成。
2. 文案有改动就重跑字形扫描；动效或时长有改动就重跑静止检测。
3. 渲染到新文件名（例如 `out/<合成名>_<日期>.mp4`），参数按 README。
4. 成片复测：
   - `python3 .agents/skills/music-graphic-video/scripts/audio_probe.py out/<成片>.mp4 --master`：True Peak ≤ -1 dBTP，音视频时长一致。超限时按报告列出的时间段压低对应音效或音轨，不要整体加限幅了事。
   - 用 `ffprobe` 核对分辨率、帧率、时长。
5. 交付成片路径、时长、参数和复测结果，并把分镜文档改成最终版。

## 五条硬红线

### 1. 节奏与完播率

- 停留时长从文字完全可读开始算，到开始退场为止：
  - **新信息**：字数 ÷ 4～5 字/秒 + 0.6～0.8 秒落焦。
  - **过渡短句**（连接词、前面出现过的词、标签，6 字以内）：0.8～1.2 秒。超过 6 字按新信息算。
  - **情绪爆点、核心结论**：先按新信息算出停留，读完后再定格 1.8～2.5 秒。
- 除爆点定格外，任何画面完全静止不超过 1.5 秒；前 15 秒的钩子区不超过 1.0 秒。钩子区不安排定格，需要强调时用慢推。用 `check_freeze.py` 检查。
- 前 1～3 秒放全片最强的画面、冲突或结论。
- 删掉同义反复的文案。字少而乐句长时，用视觉连击或双栏对比把乐句填满，不让画面干等鼓点。
- 最后一句文案（含爆点定格）结束后，片尾不超过 3 秒；音乐在乐句末尾淡出，不硬切，剩下的空尾奏全部裁掉。

原因：无旁白视频里，文字是唯一的信息来源。字幕行业的阅读速度上限（Netflix 简中 9 字/秒）是有声音辅助时的上限，画面文字只能更慢。长时间静止和空尾奏都是观众划走的高发点。

### 2. 自由运镜与焦点防裁切

推、拉、平移、路径跟随、局部特写都可以按叙事需要设计，缩放倍率不设上限。但每个镜头都要按当前视口坐标计算安全区（公式见 references/visual.md）：

- 正在呈现的核心文案和主体图形，从出场第一帧到停留结束都完整清晰，不被画框边缘或装饰元素（例如活页线圈、边框）遮挡或裁切。
- 安全区 = 画框减去边距，再减去目标平台的界面遮挡区（竖屏短视频的顶部、底部文案区和右侧按钮列）。
- 大幅局部特写时，无关的大标题和边缘元素主动淡出或移出画外，或者放在不跟镜头走的独立图层上，不能被拦腰切半。
- 位图（纸纹、照片、参考图）的像素要按“显示宽度 × 最大放大倍数”准备，否则推近会糊。文字和矢量图形不受影响。
- 用局部组件抬升高亮和重拍冲击（瞬推回弹、微震、光环星芒等）强化节奏反馈，但只放在乐句起点和爆点上；微震作用在容器或背景上，正在阅读的文字不抖。参数见 references/visual.md。

### 3. 视觉逻辑防穿帮

- 分步揭示的图形（路径、高亮线、印章、结果）在触发前进度严格为 0：`interpolate` 两端都 clamp；圆头描边在进度为 0 时隐藏，因为圆头会露出一个点；揭晓类元素触发前不挂载，或者透明度为 0。
- 计时器、进度数字和对应动效共用同一个进度值，逐帧跳动，用等宽数字。
- 在 Studio 里逐个检查触发点的前一帧。

### 4. 性能与离线字体

- 字体文件放进项目并显式加载（`@remotion/fonts` 的 `loadFont`，老项目用 `@font-face` 加 `delayRender`），不用远程字体。每个用到的字重都要有对应的字体文件，否则浏览器会合成假粗体。
- 每次增改文案后都跑 `check_glyphs.py`；有“所有字体都缺”的错误必须修（换字、换字体或补字体文件）。
- 复杂底纹（纸纹、颗粒、噪点）和重型 SVG 滤镜预先生成静态图，像素按红线 2 的要求准备，不在每帧重算。

### 5. 音效克制

- 只用 CC0 音效，来源和许可证写进 `sfx.csv`。Pixabay、Mixkit 的音效不是 CC0；Freesound 要按许可证筛选。
- 全部经过 `prep_sfx.py`：去头尾静音、按动作截短、短淡出、峰值归一化到 -6 dBFS。音效尾巴不能拖过下一个镜头的切点。
- 响度不盖过 BGM：volume 从 0.3～0.5 起试，在 Studio 里和 BGM 一起听；成片用 `--master` 复测 True Peak。
- 重拍音效只配重拍动效，不是每个元素都要配音效。

## 脚本

每个脚本都带 `--selftest`，在新环境里先跑一遍，确认依赖和结果都正常。

| 脚本 | 用途 | 依赖 |
|---|---|---|
| `scripts/audio_probe.py` | 1～2 首 BGM 的体检和衔接方案（`--target` 目标时长、`--switch-at` 切歌位置）；`--master` 复测成片 | ffmpeg、numpy |
| `scripts/prep_sfx.py` | 按清单批量处理音效，拒绝非 CC0，输出 `sfx-credits.csv` | ffmpeg |
| `scripts/check_glyphs.py` | 缺字、字重、远程字体、中文断行 | fontTools |
| `scripts/check_freeze.py` | 静止画面检测（正文 1.5 s、钩子区 1.0 s、登记的爆点 2.5 s） | ffmpeg |
